- Step 17: Hints + optional earned boosters. SugartrailHints is a deterministic legal-move ranker that never mutates state: it clones the board + RNG per candidate swap, simulates resolution, scores by REMOVE (+10), cascade (+5/step), BLOCKER_DAMAGE/BREAK (+15), TOKEN_RELEASE (+50), SPECIAL_ACTIVATE/CREATE (+12), with frosted-cell (+25) and token-release (+60) boosts, and returns the top-N scored moves with a non-empty `reason` string. SugartrailBooster is the approved booster catalog; the launch set is just SWAP_RETRY (=0). The Booster + BoosterPack classes carry inventory and a pending flag. Use is two-phase (`request_use` marks pending, `cancel` clears without consuming, `confirm` is atomic and decrements inventory by 1). Session grows `request_booster`, `cancel_booster`, `confirm_booster`, and `_apply_swap_retry`; the SWAP_RETRY effect restores the board from the pre-swap snapshot carried on the SWAP action's `extra.pre_swap_board` (captured in `attempt_swap`), refunds the move, and removes the swap from the action log so a retry cannot be applied to the same swap twice. Replay supports USE_BOOSTER (SWAP_RETRY restores from `extra.pre_swap_board`) and CANCEL_BOOSTER (no-op). Snapshot roundtrips the booster pack via `Session.snapshot_state()`. Recipe schema gains an optional `boosters` field (Array of {kind, count}). Engine bumped 0.5.0 -> 0.6.0; replay fixtures bumped to 0.6.0-test. 30 new fixtures (test_hints, test_boosters, test_boosters_integration). Total: 254/254 (253 passing + 1 risky/pending for an unreachable deadlock precondition).
- Step 18: Robust local persistence. SugartrailSaveData is a versioned local save document (schema v1) capturing level records (best score + stars + completion flag), booster inventory (with per-kind and total caps), settings (sound/music/haptics + accessibility flags + language), tutorial flags, an active session snapshot for resume, coins, player name, and integrity metadata (schema_version, FNV-1a 32-bit checksum, saved_at, engine_version, write_count). SaveData.validate checks stars 0..3, non-negative scores, booster inventory under cap, and non-negative coins. SaveData.migrate is forward-only and chains per-version migrations (currently a no-op since v1 is the launch schema). SugartrailSaveIO owns the on-disk format: write_atomic serialises the envelope, writes to <path>.tmp, flushes, copies the existing primary to <path>.bak (one-previous backup), then atomically renames temp -> primary. load reads the primary, validates the checksum + schema, and falls back to the backup on any failure, reporting recovered_from_backup=true. reset removes both files; has_save tells the application whether to start fresh. The IO layer never throws — it returns an IoResult the application can act on. Engine stays at 0.6.0 (no replay schema change). 18 new fixtures in test_save.gd (fresh install, validation, roundtrip, atomic write, backup rotation, corrupt primary recovery, no-save path, has_save, reset, migration pass-through + newer-schema rejection, write_count, active session roundtrip with and without snapshot). Total: 272/272 (271 passing + 1 risky/pending for the pre-existing unreachable deadlock precondition). Zero new lint errors.
